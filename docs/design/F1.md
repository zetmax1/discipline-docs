# F1 — The daily loop: block lifecycle, morning check-in, Today, focus sessions, block check-ins, evening shutdown

Spec: M2 item 5 (block lifecycle); M3 items 1–6. Flag: `FEATURE_F1`.
Branch `feat/F1` in `discipline`, `discipline-back`, `discipline-py`, **based on `feat/F12a`** (needs flags,
i18n, error codes, E2E setup; none merged yet).

## Stories and acceptance criteria
**S1 Block lifecycle (api, migration).** Minutes 0–1440 replace `TIME`; statuses `planned → in_progress → done |
partial | skipped | moved`; actual start/end; focus rating 1–5; note; `moved_from_id`.
- Every existing block keeps date, times, status (pending→planned, completed→done) and category (test on a
  production-shaped copy: seeded legacy rows incl. 24:00 ends and legacy invalid rows).
- Overlap checks ignore skipped and moved blocks (test).
- Old `start_time`/`end_time` columns stay (written alongside) and are dropped in a later migration.
- Legacy input `pending`/`completed` is accepted for one release (old web during deploy).
- `POST /tasks/:id/check-in` {status done|partial|skipped, actualStartMin?, actualEndMin?, focusRating?, note?}:
  actual times default to planned (or to the linked sessions' span). Idempotent (same body → same result).
- `POST /tasks/:id/move` {date, startMin, endMin} + `Idempotency-Key`: new block with `movedFromId`, old → moved.

**S2 Metrics (analytics).** Completed minutes use actual times when present; `partial` counts its actual minutes;
`done` without actual times counts planned minutes; skipped/moved count nothing. Reads the minute columns.

**S3 Morning check-in (api + web).** One per local day (`user tz`), editable the same day, skippable (stored as
skipped so other devices don't ask again). Sleep start/end in minutes; start > end means it began the previous
evening. Prefill: last check-in's sleep times, else 23:00–07:00.
- Check-in at 00:30 local belongs to the new local day; 23:30→07:00 sleep = 7 h 30 min (tests, incl. DST night).

**S4 Focus sessions (api + web).** Presets 25/5, 50/10, 90/20, custom 10–180; long break (15/20/30) after 4
completed sessions that day. The server stores start, planned minutes, break minutes, end, outcome
(completed|abandoned), distractions, linked block. Responses carry `serverNow`; clients show
`planned − (serverNow − startedAt)` corrected for clock skew → same countdown on every device (±1 s).
- Offline: actions queue in `localStorage` and sync on reconnect. The client generates the session id (UUID) =
  idempotency key; updates are absolute (`distractions: 3`, `outcome`, `endedAt`) so replays are harmless.
  Duplicate submits → exactly one session with the right data (test).
- Distraction tap; parking-lot note → `parking_lot` table (F10 turns these into inbox tasks).
- Break suggestions (walk, water, stretch, eye rest), localized, rotated. End: beep (Web Audio) + vibration
  + `document.title` change.

**S5 Block check-in (web).** One tap done / partial / skipped from Today and Planner; then a skippable focus
rating (1–5).

**S6 Today screen (web, replaces Dashboard while F1 is on).** Check-in card until done → (Top-3: F10) →
current/next block with Start → active session → today's timeline → shutdown prompt after 21:00 (device
setting until Settings exists). Empty states teach the loop.

**S7 Evening shutdown (api + web).** Unfinished blocks: move to tomorrow (same times) / later (inbox: F10, for now
"skip") / drop (skipped); one win (≤ 280 chars); tomorrow's Top-3 (F10, hidden for now). `POST /shutdowns/today`
marks the day closed (one per day, idempotent).

**S8 Product events (api).** Append-only `product_events (user_id, name, props jsonb, occurred_at)` (M1 item 11,
minimal) with names from `discipline/contracts/events.schema.json`; written by the API for: `block_created`,
`block_status_changed`, `block_moved`, `checkin_morning_done`, `session_started`, `session_completed`,
`session_abandoned`, `distraction_logged`, `block_checked_in`, `shutdown_done`. Never sent elsewhere.

## Migrations (goose, each with Down)
- `00008_block_lifecycle`: tasks + `start_min`, `end_min` (backfilled; CHECK 0≤start<end≤1440 for valid rows),
  `actual_start_min`, `actual_end_min`, `focus_rating` (1–5), `note` (≤500), `moved_from_id` (FK SET NULL);
  status mapped + CHECK. Down: statuses back (in_progress→pending, partial/done→completed, moved→skipped), drop columns.
- `00009_idempotency_keys`, `00010_checkins`, `00011_focus_sessions` (+ `parking_lot`), `00012_shutdowns`,
  `00013_product_events` (numbering as built).

## API (all behind FEATURE_F1 except the lifecycle fields on existing endpoints) and contracts
`contracts/blocks.schema.json` (Block), `daily.schema.json` (MorningCheckin, FocusSession, Shutdown),
`events.schema.json` (event names). Endpoints:
`GET/PUT /checkins/today` (PUT {skipped} or {sleepStartMin, sleepEndMin, sleepQuality, energy, note});
`GET /sessions/active`, `GET /sessions?date=`, `PUT /sessions/:id` (create or update, idempotent by id);
`POST /parking-lot`; `POST /tasks/:id/check-in`; `POST /tasks/:id/move`; `GET/POST /shutdowns/today`.
Every response that the web reads is validated in Go tests against the contracts.

## Screens (390 px first, 1440 px) — empty / loading / error / offline
Today: check-in card (sliders as 1–5 buttons, time inputs, Save / Skip) · current/next block card (Start focus,
Done/Partial/Skip) · focus timer (big countdown, distraction button with count, parking-lot input, pause-free:
Finish / Stop) · break card with a suggestion · timeline · shutdown card. Planner rows get Done/Partial/Skip.
Offline: actions show "will sync" and a pending count. Desktop: two columns (timer/check-in left, timeline right).

## i18n keys
`today.*`, `checkin.*`, `session.*`, `breaks.*`, `checkinBlock.*`, `shutdown.*`, `sync.*`, `status.*`.

## Edge cases
Midnight (check-in/session crossing 00:00 belongs to its start's local day), DST night sleep duration, offline
duplicate submits, two devices (server start time + serverNow), clock skew, new user (empty states), session left
running (> planned + 60 min → auto-abandon when read), block deleted while a session links to it (SET NULL).

## Test plan
Go: migration up/down on a production-shaped copy; status transitions; overlap ignores skipped/moved; check-in day
attribution 00:30 and DST; sessions idempotent replay; contract validation. Python: metrics with actual/partial.
Web: offline queue (dedupe, replay order), countdown with skew, check-in defaults, components. E2E 390/1440:
check-in → start session → distraction → finish → block check-in → shutdown; second tab shows the same timer;
offline session then reconnect → one session.

## Decisions taken without a stop (owner asked to proceed without stopping)
1. Top-3, task inbox, "later" in shutdown → F10; parking-lot notes stored now, turned into inbox tasks in F10.
2. Shutdown prompt time 21:00 and sleep prefill 23:00–07:00 are device defaults until Settings/onboarding exist.
3. Minimal `product_events` table now (M1 item 11 isn't in any feature prompt).
4. Session distraction counts are absolute values (last write wins); simultaneous taps on two devices may merge.
5. Category stays a string (kinds arrive with F13).

## Open questions

- Long-break length: 15 min for 25/5, 20 for 50/10, 30 for 90/20 — acceptable?

## Build notes (what changed while building)
- **Rolling deploy:** migration 00008 adds a trigger that keeps the TIME columns and the minutes in sync and maps
  `pending`/`completed`, so the previous API version keeps working while the new one rolls out. The trigger goes
  with the TIME columns in a later migration.
- **Idempotency keys** store the created resource id (not the response) and are checked inside the move's
  transaction, so concurrent replays can't create two blocks.
- **Events** are recorded by the services only on real transitions; replays write nothing (tested).
- **Race fixed:** starting a session before the "active session" query answered used to drop the new session.
- **Rating prompt:** the list refreshes after the rating, not before (found by E2E).
- **Not built yet (follow-ups):** check-in actual times default to the *planned* times only — defaulting to the
  linked sessions' span is open; a morning check-in queued offline across midnight lands on the day it syncs;
  Top-3 and "later" in the shutdown wait for F10.
