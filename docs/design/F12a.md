# F12a — Uzbek/Russian/English UI, dark mode, mobile app shell

Spec: M1 item 6 (i18n), item 7 (mobile-first shell), Should "Dark mode via design tokens".
Flag: `FEATURE_F12A`. Repos: `discipline` (web), `discipline-back` (api), `discipline-py` (analytics).
Branch: `feat/F12a` in each repo. **Base: `feat/F0`** in web and api (F12a needs the flag endpoint, `<Feature>`,
Playwright and the Go contract helper, which are not merged yet); `fix/phase-5` in analytics.
Out of scope: push notifications (F2), saving the language on the server (M1 Settings/Onboarding), legal pages.

## Stories and acceptance criteria

**S1 — Stable API error codes (api).** Every JSON error response is `{"error": <English text>, "code": <code>, …}`.
- AC: no handler/middleware writes an error body without a code (source-scan test).
- AC: the codes in `apierr` equal the enum in `discipline/contracts/errors.schema.json` (Go contract test); sample
  error bodies validate against it.
- AC: task validation errors carry a specific code (e.g. `task_end_before_start`), not only `validation_failed`.
- Additive: `error` text stays, so today's web keeps working.

**S2 — Structured analytics text (analytics).** Smart-schedule responses gain `reasons: [{code, category, …}]`
and each block gains `label` (`deep_work | study | light_study | rest | null` for commitments).
The English `reasoning` / `name` stay for old clients. Period-report insights are rebuilt in the web from the
structured fields that already exist (`best_weekday`, `peak_hour`, `trend`, `consistency_score`).
- AC: the analytics contract test is green with the new fields; the web parses them.

**S3 — i18n (web).** All UI text comes from `src/i18n/` dictionaries (`en` is the source, `uz`, `ru` typed against it).
- AC: flag on → default `uz` (Latin); switcher on the login page and in the app (menu); choice kept in `localStorage`.
- AC: flag off → `en`, no switcher; every screen looks exactly as before.
- AC: `<html lang>` follows the language; dates, weekdays, numbers and percentages via `Intl` in that locale.
- AC: API errors are shown from `errors.<code>`; unknown code → the server's text (never a generic "failed").
- AC: `npm run check` fails on a hardcoded UI string (ESLint rule `local/no-ui-literal`) and on a missing,
  extra, empty or mis-parameterised key in any language (tsc + `src/i18n/messages.test.ts`).

**S4 — Dark mode (web).** Design tokens already exist (`.dark` in `index.css`); `next-themes` (MIT, installed).
- AC: flag on → theme Light / Dark / System (default System) in the app menu and login page; kept in `localStorage`.
- AC: flag off → forced light.
- AC: text/background token pairs meet WCAG AA in both themes (contrast test on the tokens).

**S5 — Mobile shell + PWA (web).**
- AC (flag on): below 768 px a bottom navigation (5 items, ≥ 44 px targets, active state, safe-area padding)
  replaces the sidebar; a top bar holds the app menu (language, theme, profile, sign out). ≥ 768 px: sidebar.
- AC (flag on): manifest + service worker registered; installable (name, icons 192/512 + maskable, `display:
  standalone`, start_url `/`); the app shell is cached; with the network off a navigation shows the cached app,
  or `offline.html` if the shell was never cached. `/api` is never cached.
- AC: an offline banner shows on every screen while `navigator.onLine` is false (flag on).
- AC (flag off): no service worker is registered, and one registered earlier is removed.

**S6 — E2E.** Playwright: language switch (uz → ru → en) on login and planner, dark mode, bottom nav at 390 px,
offline banner; screenshots 390/1440 px → `docs/design/F12a-screens/`.

## API + contract schemas
- New web contract `contracts/errors.schema.json` → `{ error: { error: string, code: enum ErrorCode, …loose } }`.
- Codes (snake_case, stable): `internal_error, not_found, method_not_allowed, body_too_large, origin_not_allowed,
  rate_limited, service_unavailable, auth_required, token_invalid, forbidden, user_not_found, validation_failed,
  invalid_credentials, captcha_required, login_throttled, email_taken, password_too_short, password_too_long,
  current_password_required, current_password_incorrect, invalid_timezone, task_not_found, task_id_invalid,
  task_name_length, task_date_invalid, task_time_invalid, task_end_before_start, task_category_invalid,
  task_energy_invalid, task_status_invalid, task_distractions_invalid, task_overlap, plan_week_invalid,
  word_not_found, word_id_invalid, date_invalid, range_invalid, days_invalid, analytics_unavailable,
  analytics_validation_failed`.
  (`plan_week_invalid` only if SavePlan's own week check needs it; the enum and `apierr` are kept equal by test.)
- `contracts/analytics.schema.json#smart_schedule`: `reasons[]` = `{code: learned|default|shortfall, category,
  start_time?, blocks?, minutes?}`; block `label` (nullable). Both optional in zod for one release (old analytics
  service), required in the Python model.

## i18n keys
Namespaces in `src/i18n/en.ts`: `common.*`, `nav.*`, `menu.*`, `shell.*` (offline, bottom nav), `auth.*`, `dashboard.*`,
`planner.*`, `analytics.*`, `schedule.*`, `vocabulary.*`, `profile.*`, `notFound.*`, `demo.*`, `categories.*`,
`weekdays.*`, `errors.<code>`, `messages.*` (encouraging toasts). Plurals: `key_one|_few|_many|_other` chosen with
`Intl.PluralRules` (ru needs one/few/many; uz and en one/other). Params: `{name}`. `en.ts` is the full list.

## Edge cases
- **Timezone/DST, midnight:** no new date logic; existing helpers stay. Weekday/date labels come from `Intl` with
  the user's IANA zone where a zone is known, so a date never shifts a day at midnight (tests at 23:59 / 00:00 and a
  DST-switch date).
- **Offline:** SW serves the cached shell; API calls fail and the screens show their (translated) error/offline state.
  The flag value is cached in `localStorage` so an offline start keeps the same shell.
- **Several devices:** language and theme are per device until Settings stores them on the server.
- **New user / signed out:** flags are only served to signed-in users. Before sign-in the web uses the last flag value
  seen on this device (default off → English). Once F12A is accepted and the flag removed, everyone gets `uz` first.
- **Unknown locale in storage / unsupported Intl locale:** fall back to the default language; `Intl` falls back itself.
- **Long translations:** bottom-nav labels truncate with ellipsis; buttons wrap; tested at 390 px in `ru`.
- **Flag turned off later:** SW unregistered, caches deleted, language back to `en`, theme light.

## Decisions taken without a stop (owner asked to proceed without stopping; change any of these)
1. **No i18n library**: typed dictionaries + `Intl.PluralRules` (~1 KB, missing keys fail `tsc`). i18next would add
   ~25 KB gz for features we don't use yet.
2. **Hardcoded-string check** = a local ESLint rule (JSX text, UI attributes, toast arguments). Strings built in plain
   `.ts` modules can't be detected reliably; they live in dictionaries by convention.
3. **Signed-out screens** use the last flag value seen on the device (flags are only served to signed-in users).
4. **Service worker** is hand-written (`public/sw.js`), no Workbox/vite-plugin-pwa dependency.
5. **Uzbek and Russian text** is written by the developer, not a professional translator — owner review advised
   (all text is in `discipline/src/i18n/uz.ts` and `ru.ts`).
6. **Smart-schedule and insights text** become structured data translated in the web (touches analytics).

## Build notes (what changed from the design while building)
- **Touch targets:** existing screens had many controls under 44 px. With F12A on and below 768 px, CSS in
  `index.css` (scoped by `html[data-shell="f12a"]`) sets 44 px minimums; planner rows and vocabulary filters
  wrap. An E2E check measures every visible control and sideways overflow on all five screens at 390 px.
- **Uzbek formats:** browsers (Chromium) claim Uzbek `Intl` support but print fallback data ("M10 30, Fri",
  "1.5"). Uzbek dates and numbers use built-in CLDR names/patterns (`src/i18n/translate.ts`); ru/en use `Intl`.
- **Token contrast:** a test checks 16 text/background pairs for AA in both themes; five token values changed
  slightly (light muted text and accent green, dark muted text, dark destructive, dark sidebar-primary text).
- **Removed dead code** that only held untranslated text: `pages/Index.tsx`, `ui/pagination|carousel|command|
  breadcrumb`. Their npm dependencies (`embla-carousel-react`, `cmdk`) are now unused but left installed.
- **E2E** runs against a production build (`vite preview`) so the service worker is exercised.
- **Known gap → F4:** the server-rendered PNG charts on Analytics (heatmap, category split, distraction trend)
  still contain English labels inside the images. F4 draws charts in the browser.
- **Demo data** (`SAMPLE_TASKS`, demo vocabulary) and API content (quotes, dictionary words) are content, not UI,
  and stay as they are.
- Signed-out screens follow the flags last seen on the device: a first-time visitor sees English until the flag
  is removed after acceptance.
