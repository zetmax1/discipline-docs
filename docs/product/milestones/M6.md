# M6 — Learning engine, insights, weekly review

**Goal:** a suggested weekly plan that fits the person better than their own first draft, explained in plain words. Design only after ≥2 weeks of beta data.

## Must
1. **History and drafts**
   - Append-only events for block outcomes, sessions, check-ins and suggestion outcomes.
   - `plan_drafts`: user, week, version, inputs hash, blocks, reasons, created_at. A new generation creates a new version; old versions stay.
2. **Model** (per user × category kind, on a 7 × 48 half-hour grid)
   - Success rate smoothed as `(done + 1) / (planned + 2)`.
   - Mean focus rating per slot.
   - Recency weight `0.5^(age_days / 14)`.
   - Routine detection: a slot occupied in ≥3 of the last 4 weeks → suggest it as a commitment (the user confirms).
   - Planning-fallacy ratio per kind (median actual / planned duration), used to size suggested blocks.
3. **Placement** (greedy v1; a solver only if v1 measurably fails)
   - Fill goal minutes into free slots by score.
   - Constraints: no overlap with commitments or existing blocks; focus blocks 60–120 min; 10–15 min buffers; max focus per day; sleep window and wind-down respected; rest day respected.
   - Deterministic for the same inputs (seeded tie-breaks).
   - Every block carries a reason built from real numbers ("You completed 82% of focus blocks on Tue 08:00–10:00").
   - Shortfalls reported per category.
4. **Cold start:** fewer than 14 days or 20 completed blocks → template from onboarding chronotype + commitments, labeled "Not learned yet — N more days".
5. **Draft review UI:** week view of the draft over commitments; edit, move, delete, accept all or per day. Record accepted / edited / deleted per suggested block.
6. **Insights with client-side charts** from JSON (Recharts): heatmap, completion, best hours, planning fallacy, sleep/energy vs focus (worded as correlation; minimum days enforced). Remove the server PNG pipeline, matplotlib and its cache.
7. **Weekly review** (Sunday, ≤ 3 minutes): last week in numbers, one reflection question, adjust goals, generate and accept next week's draft.
8. **Offline evaluation script:** replay beta weeks; compare suggested slots with actual outcomes; report acceptance rate and completion of suggested vs self-planned blocks. No automatic tuning.

## Acceptance criteria
- Same inputs → identical draft (test).
- No suggested block violates any constraint (property tests over random weeks).
- Every suggested block has a reason; no text claims learning when the cold-start rule applies.
- No "AI" wording anywhere in this feature.
- Evaluation report produced from beta data before the flag is turned on for everyone.

## Events
`draft_generated`, `draft_accepted`, `suggestion_edited`, `suggestion_deleted`, `routine_suggested`, `routine_accepted`, `review_completed`.
