# M2 — Planner v2

**Goal:** plan a week in under 5 minutes, and give every block a lifecycle the learning engine can learn from.

## Must
1. **Categories**
   - Table per user: name, color, icon, `kind` (`focus`, `study`, `admin`, `exercise`, `rest`, `personal`). Defaults seeded at signup (Deep Work=focus, Study=study, Admin=admin, Exercise=exercise, Rest=rest, Personal=personal).
   - Migrate existing `tasks.category` strings to `category_id` (gym → Exercise).
   - Metrics (`app/metrics.py`) switch from category strings to `kind`; update contracts and fixtures.
2. **Commitments on the server** (closes F-29 and the overnight leftover of F-08)
   - Fields: name, weekdays, start/end minutes, valid_from, valid_to (optional), category kind for display.
   - End before start = crosses midnight: expanded as two segments (day D start→1440, day D+1 0→end).
   - One-time import of the localStorage commitments/goals the current Smart Schedule page saved, then clear them.
   - Onboarding gains a commitments step with templates: university timetable, work shifts.
3. **Goals on the server:** weekly minutes per category, max focus minutes per day, preferred rest day (from M1 onboarding).
4. **Block lifecycle**
   - Times stored as integer minutes 0–1440 (replaces `TIME`; removes the 24:00 workaround).
   - Status `planned → in_progress → done | partial | skipped | moved`; `moved` creates a new block with `moved_from_id`.
   - Actual start/end; focus rating 1–5 asked after done/partial (skippable); optional note.
   - Skipped and moved blocks do not count for overlap checks.
   - Migration converts existing rows; old columns removed only in a later migration.
5. **Views**
   - Day: timeline 00:00–24:00, scrolls to now, commitments drawn as hatched background.
   - Week: 7 columns, same rules.
   - Create, move and resize by drag in 15-minute steps (desktop) and long-press + drag (mobile); a form-based alternative for keyboard and screen-reader users.
6. **Recurring blocks:** daily, weekdays, or chosen weekdays; until a date or forever; exceptions; edit "this one" or "this and following". Occurrences materialized per week when that week is viewed or planned.
7. **Tasks and Top-3:** tasks table (title, done, optional due date, optional linked block); Top-3 per day (max 3, ordered); an inbox for unscheduled tasks.
8. **Smart Schedule page** reads commitments and goals from the server. The generator keeps its current logic (redesign is M6); "Save plan" keeps the `plan_id` replace behaviour.

## Acceptance criteria
- A user with a university timetable and gym 3×/week can plan a full week in under 5 minutes on a phone.
- Overnight commitment (23:00–07:00, Mon–Fri) blocks Mon 23:00–24:00 and Tue 00:00–07:00, and not Mon 00:00–07:00 (test).
- Every existing block survives the migration with the same date, times, status and category (migration test on a production-shaped copy).
- Drag on touch devices doesn't fight page scrolling.
- Overlap check ignores skipped/moved blocks (test).

## Events
`block_created`, `block_status_changed`, `block_moved`, `week_planned` (blocks on ≥5 days of a week), `top3_set`, `commitment_created`.

## Out of scope
Focus timer and check-ins (M3), learning engine (M6).
